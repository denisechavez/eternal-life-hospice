Confirmed defects

Findings register

ELH-F-001 — Care Brief redirect loop

High

Category: Crawlability, redirects, sitemap and AI readiness   Status: Confirmed

Affected URL: https://eternallifehospice.com/care-brief

Evidence:

/care-brief  → 301 Location: /care-brief/
/care-brief/ → 301 Location: /care-brief

The URL is included in sitemap.xml, main navigation, footer navigation, breadcrumb schema, internal links, and llms.txt. The direct file /care-brief.html returns HTTP 200.

Impact: Google and AI crawlers cannot reach the Care Brief archive through the intended canonical route, and users can encounter a redirect error.

Recommended fix: Make /care-brief the one canonical HTTP 200 route. Redirect /care-brief/ to it in one hop, and keep sitemap, canonical, navigation, schema, and llms.txt aligned.

Aesthetic impact: None expected. Technical approval only.

ELH-F-002 — HTTPS www hostname fails TLS

High

Category: Canonical domain, crawlability and deployment   Status: Confirmed

Evidence: Three independent HTTPS attempts to https://www.eternallifehospice.com/ failed with a TLS “unexpected EOF” error and HTTP status 000.

HTTP currently responds with:

http://www.eternallifehospice.com/
→ 301 Location: https://www.eternallifehospice.com:443/

Impact: Visitors, crawlers, old bookmarks, listings, and backlinks using the www hostname can fail before reaching the canonical site.

Recommended fix: Confirm the www custom domain and certificate in the active Replit deployment. Configure a direct 301 from www HTTPS to the non-www canonical domain, preserving path and query string.

Aesthetic impact: None. Requires domain/DNS and deployment access.

ELH-F-003 — Production disables browser caching

High

Category: Performance and deployment   Status: Confirmed

Production returned Cache-Control: no-store for sampled homepage HTML, CSS, JavaScript, JSON, and image responses. The active Python server applies no-store whenever a response does not already have another cache policy. The Netlify _headers file is not automatically applied by the Replit Python server.

Sampled assets included:

  • Homepage HTML: approximately 247 KB
  • Shared CSS: approximately 60 KB
  • Header JavaScript: approximately 13 KB
  • Search index JSON: approximately 71 KB
  • Somis JPEG: approximately 8.87 MB

Impact: Repeat visits redownload or revalidate assets unnecessarily, increasing bandwidth and mobile load time.

Recommended fix: Add endpoint-specific caching in the active Replit server. Use short revalidation for HTML and longer public caching for versioned static assets.

Aesthetic impact: None if implemented as HTTP headers only.

ELH-F-004 — No observed production compression

High

Category: Performance   Status: Confirmed for sampled responses

Requests sent with compression support did not receive Content-Encoding: gzip or Content-Encoding: br.

Impact: Larger text transfers and slower first visits on mobile networks.

Recommended fix: Enable Brotli or gzip for HTML, CSS, JavaScript, JSON, XML, and SVG. Do not recompress JPEG, PNG, WebP, PDF, or other already-compressed formats.

Aesthetic impact: None. Technical approval only.

ELH-F-006 — Missing explicit image dimensions

Medium

Category: Performance and layout stability   Status: Confirmed

Across the 177 sitemap pages, 631 image occurrences lack either an explicit width or height.

Impact: The browser may not reserve image space before loading, creating layout-shift risk under slower network conditions. The prior Lighthouse baseline showed CLS 0, so this is preventive rather than proof of a current field CLS failure.

Recommended fix: Add accurate intrinsic dimensions while preserving responsive CSS such as max-width:100%; height:auto;. Verify mobile, tablet, and desktop screenshots before release.

Aesthetic impact: Possible if dimensions are inaccurate. Visual regression testing required.

ELH-F-007 — Image loading strategy is not explicit on many images

Low–Med

Status: Confirmed inventory; not every occurrence is a defect

Across sitemap pages, 355 image occurrences have neither loading nor fetchpriority. The city-page guard confirms that all 145 city pages have a WebP hero preload and appropriate hero markup.

Recommended fix: Classify images by position: eager/high priority for LCP heroes, default for immediately visible supporting images, and lazy loading for below-the-fold content. Do not lazy-load every image automatically.

ELH-F-008 — Large fallback JPEG inventory

Info–Med

Status: Confirmed inventory; active transfer risk is mitigated for modern browsers

85 deployable assets exceed 500 KB. Seventy-three city JPEGs exceed 500 KB. The largest are Somis at 8.87 MB and Stevenson Ranch at 8.75 MB.

All 73 large city JPEGs have WebP versions. For example, Somis is approximately 8.87 MB as JPEG versus 92 KB as WebP, a 99% reduction.

Recommended fix: Do not delete or replace approved imagery automatically. Review whether fallback JPEG quality can be reduced while preserving the approved crop and appearance.

ELH-F-009 — Production does not apply repository security headers

Medium

Status: Confirmed

Live sampled HTML included HSTS, but did not include the repository’s intended Content-Security-Policy, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, or frame restrictions.

The Netlify fallback CSP also needs review because it combines frame-src 'none' with another frame source and does not clearly cover every active third-party runtime host.

Impact: This is not a direct ranking defect, but it weakens browser security and creates inconsistent behavior between Replit and the frozen Netlify fallback.

Recommended fix: Define appropriate headers in the active Replit server or supported edge, then test chat, forms, UserWay, Metricool, WhatConverts, Clarity, Brevo, and analytics before tightening CSP.

Aesthetic impact: Normally none. Widget behavior must be browser-tested.

ELH-F-010 — Duplicate Netlify build configurations

Medium

Affected files: netlify.toml and website/elh-preview/netlify.toml

The root configuration uses website/elh-preview as its base, strips form-routing attributes, and runs the full predeployment chain. The nested configuration assumes the site directory is the root, regenerates city data and the search index, and invokes a PageSpeed plugin.

Impact: The active Replit deployment is not dependent on these files, but the frozen Netlify fallback could build differently depending on which configuration Netlify treats as authoritative.

Recommended fix: Verify the Netlify project base directory and dashboard build settings before deciding which file is authoritative. Do not change either file blindly.

ELH-F-011 — Alternate Replit hostname serves a duplicate copy

Low–Med

Affected hostname: https://eternal-life-hospice.replit.app

The Replit hostname returns HTTP 200 and body content identical to the canonical hostname. Page canonicals correctly point to https://eternallifehospice.com.

Impact: Current canonicals provide duplicate-content protection, but two publicly accessible hostnames create unnecessary crawl surfaces.

Recommended fix: If feasible, redirect normal HTML page requests on the Replit hostname to the canonical domain while preserving required API and proxy routes. Audit the form/chat architecture before redirecting APIs.
