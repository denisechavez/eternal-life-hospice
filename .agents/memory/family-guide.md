name: family-guide booklet
description: Gotchas for editing website/elh-preview/family-guide.html (the interactive booklet)
---

- [Page-turn timing is duplicated](#) — the booklet flip duration lives in BOTH CSS (`body.booklet .page{transition:transform ...}`) and JS (`setTimeout(restingZ, <ms>)` in `go()`). **Why:** the JS timer resets z-index after the flip; if it doesn't match the CSS duration the leaf snaps or flickers. **How to apply:** change both together (CSS ms + JS ms, JS slightly larger as buffer).

- [Appended overrides re-break reduced-motion](#) — the file has an early `@media(prefers-reduced-motion:reduce){body.booklet .page{transition:opacity .3s ease}}`. Any later same-specificity `body.booklet .page{transition:...}` override re-enables full motion for reduced-motion users. **How to apply:** after adding a motion override, re-assert the reduced-motion block AFTER it (last in source wins).

- [QA cannot use screenshots](#) — the page shows a `#bootveil` intro that hides content ~3s (`setTimeout(revealGuide,3000)`) and content lives in a no-scroll booklet/stack. `app_preview` screenshots only ever capture the cover. **How to apply:** verify via reading CSS + `curl` (HTTP 200 + asset 200s), not screenshots.

- [Mobile worksheet restack](#) — the comparison `table.ws` is transposed to per-question cards under `@media(max-width:640px)`. Agency-name inputs live in `<thead>`; do NOT `display:none` the whole thead (loses editable names) — keep thead as a flex row of pills. Card cell labels are positional via `td.cell:nth-of-type(2/3/4)` (CSS can't read input values).

- [Fonts are externalized](#) — @font-face uses shared `assets/fonts/*.woff2` (Fraunces-var, Fraunces-Italic-var, JostELH-Light/Regular/Medium/SemiBold), not inline base64. Keeps file ~430KB. The old `ELH_Family_Guide_Interactive.html` twin was deleted (0 inbound links; `family-guide.html` is canonical).

- [Cover is NOT a numbered page](#) — there are 6 `.page` leaves: leaf 0 = cover (its own footer, no folio), leaves 1–5 = content. **Decision:** numbering counts content only — bottom `#pageLbl` reads "Cover" on the cover then "1 / 5"…"5 / 5"; per-page folio `pf-r` = `idx + ' / ' + (N-1)`; dots are generated for `d=1..N-1` (5 dots, none for the cover) and toggled by `data-i===cur`. **Why:** counting the cover made the first content page read "2 / 6" (off-by-one) which the user flagged. Don't reintroduce the cover into the count or dots.

- [Print must be EXACTLY 6 sheets — one leaf per sheet](#) — the booklet is 6 `.page` leaves (cover + 5); on-screen each leaf has `min-height:1020px` (~10.6in) for the booklet look, so printing must collapse that or each leaf spills to a 2nd sheet (12 total). **The fix that works (verified, not guessed):** (1) **Decisive root cause of "12 sheets":** the base `.page{min-height:1020px}` was NOT reset in print, so every leaf stayed taller than a sheet. You MUST add `min-height:0!important` to `.page` in BOTH the `@media print` block AND the `body.printing` block — without it no content scaling helps, the box stays 1020px. (2) Shrink content with CSS **`zoom`** (a number, e.g. `el.style.zoom=0.84`), NOT `transform:scale` — `zoom` shrinks the actual layout box so the print engine paginates the smaller size; `transform` leaves the box full-height. JS wraps each `.page`'s children in `.printwrap`, measures `scrollHeight`, sets zoom when it exceeds `PRINT_AVAIL_PX`. (3) Keep `PRINT_AVAIL_PX` **conservative = 9.0in*96**, not the full ~9.9in printable: screen-media measurement differs slightly from print-media render, so 9.6in left one leaf at ~10.2in → 7 sheets; 9.0in gives slack and survives browser headers/footers being ON. (4) Run the fit synchronously in the print button `onclick` BEFORE `window.print()` because **Safari/some browsers never fire `beforeprint`**; keep `beforeprint` + `matchMedia('print')` listeners too for Ctrl+P, all guarded by a `printing` flag; teardown is EVENT-DRIVEN (`afterprint`/mql-false), never a `setTimeout`. **Why a `body.printing` class, not only `@media print`:** JS measures in screen media, so the print layout must exist as a class for `scrollHeight` to match; `@media print` mirrors sizing as a no-JS fallback. `@page{size:Letter;margin:14mm}`, `.page width:7.4in`, `.pfoot` hidden in print. **Verify with ground truth:** install system `chromium` + npm `puppeteer`, load the page, `page.evaluate(()=>window.dispatchEvent(new Event('beforeprint')))` to apply the fit, `page.pdf({preferCSSPageSize:true})`, count `/Type /Page` in the PDF — must be 6.

- [Site-wide fixed UI pollutes every printed sheet](#) — the chat widget injected by `assets/chat.js` is `position:fixed` (`.elhc-dock`/`.elhc-panel`); fixed elements REPEAT on every printed page ("a dot on every sheet"). Canonical hide rule lives inside chat.js's own injected `<style data-elhc>` (`@media print{.elhc-dock,.elhc-panel{display:none!important}}`) so it covers all 31 pages, with backups in the booklet's print blocks. **How to apply:** any future floating/fixed UI (cookie bars, back-to-top, banners) must be added to a print-hide rule or it pollutes every printout.

- [Contact colophon — no orphaned numbers](#) — in `.contact .info`, each phone/email unit is wrapped in `<span class="ph">` with `white-space:nowrap` so a number never wraps away from its label; separators are `<span class="sep">·</span>` (opacity .5, inherits theme color). No "A Conduit International build" credit on the booklet (user removed it — only the standard 31 pages carry the Conduit credit).

- [Clean booklet resting state](#) — in Booklet mode, only the active leaf should remain visible after a turn; future leaves may be exposed only while the turn animation is running. **Why:** permanently visible under-leaves with different heights create a staggered pile at the bottom and make the guide look broken. **How to apply:** keep under-leaves transparent and non-interactive at rest, temporarily expose them with the turning-state class, and remove that class when the CSS turn duration finishes; Scroll mode remains fully stacked.

- [Skip-link first paint](#) — the Family Guide skip link needs an inline off-screen style as well as the stylesheet rule. **Why:** the large inline document stylesheet and boot veil can otherwise allow a brief visible flash before normal styles settle. **How to apply:** preserve the inline hide and use `!important` only for the focused reveal so keyboard users can still access it.
